# عباقرة البكالوريا — امتحان اللغة العربية

واجهة عربية متجاوبة، حسابات باسم مستخدم وكلمة مرور، 20 سؤالًا في 30 دقيقة، ثلاث محاولات، تصحيح اختيارات ومقالي، نتائج شخصية ولوحة شرف حسب أفضل نتيجة نهائية. لوحة الإدارة تعرض الطلاب وتصحح المقالي. خدمات Firebase جاهزة للإعداد والاختبار؛ لم يتم نشرها تلقائيًا.

## الحالة الحالية

- النسخة الأصلية كانت ملف واجهة فقط، بلا حسابات أو أسئلة أو نتائج محفوظة.
- هذا التغيير يضيف الواجهة ومحرك الامتحان وخدمات الخادم والاختبارات.
- **الامتحان يبقى مغلقًا** إذا لم يوجد مستند أسئلة معتمد منشور.
- يلزم استكمال `apiKey` من إعداد تطبيق Firebase في `js/config.js`، ونشر الوظائف والفهارس بعد مراجعتها.
- لا يحتوي المشروع على أسئلة منهج معتمدة. راجع `exam-drafts/README.md` وأرسل المحتوى الذي اعتمده مدرس المادة.
- لا تغيّر مشاريع Firebase الأخرى. المشروع المستهدف حصريًا: `abakara-baccalaureate-b0758`.

## التشغيل والبناء

Node.js 22 وJava 21+ للمحاكاة. الواجهة تحتاج بناء عند تغيير ملفات `js/`، وملفات `dist/` الملتزمة في Git تعمل مباشرة على GitHub Pages دون خطوات بناء على GitHub.

```bash
npm ci
npm ci --prefix functions
npm test
npm run build
npm run check
npm run serve
```

افتح `http://localhost:8080`. قبل استكمال الإعداد ستظهر رسالة أن التسجيل غير متاح، ولن يُرسل النموذج بيانات.

## اختبار معزول بدون مشروع الإنتاج

```bash
npm run test:emulator
```

يستخدم `demo-abakara` فقط. ينشئ حسابات اختبار وأسئلة اصطناعية داخل المحاكيات، ويختبر المعاملات المتزامنة والصلاحيات وانتهاء الوقت والتصحيح وحد المحاولات. لا يستعمل بيانات الإنتاج.

لاختبار الهاتف والكمبيوتر ثبّت متصفح الاختبار: `npx playwright install chromium` ثم شغّل `npm run test:emulator:all`.
إذا لم تسمح بيئة التشغيل بمقابس Unix، استعمل `npm run test:emulator:all:tcp`؛ يشغّل نفس دوال HTTP الفعلية على TCP محلي مع محاكي Auth وFirestore. راجع [تقرير التنفيذ](docs/IMPLEMENTATION_REVIEW.md).

للاختبار اليدوي:

```bash
npx firebase emulators:start --project demo-abakara --only auth,firestore,functions
npm run serve
```

افتح `http://localhost:8080/?emulator=1`. خيار المحاكاة يعمل فقط على localhost و127.0.0.1. لا تُستخدم المفاتيح أو البيانات الحقيقية.

## إعداد الإنتاج — بعد المراجعة والموافقة

1. راجع كود الوظائف وقواعد Firestore والفهارس. لا تنفذ النشر قبل مراجعة إعدادات المشروع وقواعده الحالية. ملف القواعد المقترح يمنع كل وصول مباشر من المتصفح؛ الخدمات تمر عبر callable functions وتعيد حقولًا محددة لكل صلاحية.
2. من Firebase > Project settings > تطبيق الويب المعتمد، انسخ **إعداد تطبيق الويب العام** إلى `js/config.js`. لا ترسل أو تضع مفتاح حساب خدمة في الكود. `apiKey` العام لا يمنح صلاحيات إدارة.
3. فعّل Email/Password وأضف نطاق GitHub Pages إلى Authorized domains. لا تعتمد على Anonymous Auth لهوية طالب دائمة.
4. يستعمل اسم المستخدم بصيغة بريد داخلية `username@students.abakara.invalid`. المستخدم يكتب اسم المستخدم وكلمة المرور فقط. الأسماء غير حساسة لحالة الأحرف، والتفرّد تفرضه Firebase Authentication، ثم يُحجز سجل الاسم في معاملة ذرية مع ملف الطالب. عند انقطاع إنشاء الملف يستطيع الطالب تسجيل الدخول واستكماله. الحسابات التجريبية القديمة ذات البريد الحقيقي لا تنتقل تلقائيًا.
5. وظائف Cloud Functions والمهام المجدولة تتطلب إعداد فوترة مناسبًا؛ راجع ذلك في المشروع قبل تفعيل الخدمات. لا يفعّل هذا الكود الفوترة.
6. سجّل دخول Firebase CLI بالحساب المخوّل. راجع نشرًا مقيدًا لهذه الوظائف، دون وظيفة تيليجرام الاختيارية:

```bash
npx firebase deploy --project abakara-baccalaureate-b0758 --only functions:completeProfile,functions:home,functions:startAttempt,functions:getAttempt,functions:saveAnswers,functions:submitAttempt,functions:leaderboard,functions:loginEvent,functions:pendingReviews,functions:adminStudents,functions:adminAttempt,functions:gradeEssay,functions:expireAttempts
npx firebase deploy --project abakara-baccalaureate-b0758 --only firestore:indexes
```

نشر `firestore:rules` خطوة مستقلة بعد مراجعة المستخدم للقواعد الحالية؛ لا تنفذ `firebase deploy` بدون `--only`.

7. بعد استكمال الإعداد شغّل `npm run build` وراجع الفرق قبل دمج التغيير الذي تنشره GitHub Pages. لا تتضمن هذه التهيئة تغيير استضافة Firebase الحالية.

## إعداد المشرف والحسابين المستثنيين

لا يملك أي طالب صلاحية إدارة تلقائيًا. باستخدام Application Default Credentials على جهاز مخوّل، حدّد المشروع صراحة:

```bash
export GOOGLE_CLOUD_PROJECT=abakara-baccalaureate-b0758
node scripts/admin.mjs ACTUAL_ADMIN_UID admin true
node scripts/admin.mjs FIRST_EXCEPTION_UID unlimited true
node scripts/admin.mjs SECOND_EXCEPTION_UID unlimited true
```

هذه أوامر كتابة فعلية؛ تُنفّذ فقط بعد اعتماد هويات الحسابات. احصل على UID الصحيح من Authentication، ولا تستخدم أسماء الطلاب لتعيين الصلاحيات. تظل صلاحية المشرف والاستثناء منفصلتين. بعد تعديل الصلاحيات يجب الخروج والدخول. رابط `admin.html` يظهر للمشرف فقط، والتحقق الحقيقي يتم داخل كل وظيفة خادم.

لا يوجد استرجاع عبر البريد الداخلي. يستطيع المشرف استعادة الحساب بعد التحقق من هوية الطالب باستخدام `reset-password` وبيئة `NEW_STUDENT_PASSWORD`؛ لا تكتب كلمة المرور في المستودع أو مخرجات السجل. يُلغى تحديث جلسات الحساب عند إعادة التعيين. إعداد جديد تلقائي لتغيير كلمة المرور غير موجود بعد.

## محتوى الامتحان

حمّل JSON معتمدًا خارج مجلد استضافة الواجهة. راجع مثال الهيكل في `exam-drafts/README.md`.

```bash
export GOOGLE_CLOUD_PROJECT=abakara-baccalaureate-b0758
node scripts/seed-exam.mjs /absolute/path/reviewed-exam.json
# الأمر السابق يحفظه مغلقًا. النشر خطوة صريحة بعد الموافقة:
node scripts/seed-exam.mjs /absolute/path/reviewed-exam.json --publish
```

التحقق يرفض العدد أو المجموع أو المدة غير المعتمدة، تكرار المعرفات، غياب أحد الموضوعات الخمسة، غياب المقالي أو الاختيارات، وغياب المراجعة ومفاتيح التصحيح. لا ترفع مفاتيح التصحيح إلى GitHub Pages. لكل محاولة نسخة خاصة محفوظة خادميًا، ولا تتأثر بتعديل الأسئلة لاحقًا.

## سياسة المحاولات والنتائج

- تُحتسب المحاولة عند نجاح إنشائها، ويُستأنف النشط بدل فتح محاولة جديدة. الحد لكل UID ولكل امتحان؛ إنشاء حساب جديد هو هوية جديدة، ولا يمثل هذا النظام تحقق هوية وطنية أو منعًا للطلاب من إنشاء حسابات متعددة.
- وقت البداية والنهاية من الخادم، 1800 ثانية. الساعة المعروضة تستخدم الزمن المتبقي من الخادم وعدادًا رتيبًا؛ تغيير ساعة الجهاز لا يمنح وقتًا إضافيًا.
- الحفظ التلقائي بعد 900ms من آخر تعديل، وحفظ يدوي. التغييرات غير المرسلة تبقى في الصفحة المفتوحة فقط. فشل الشبكة لا يعرض نجاحًا وهميًا. لا توجد قاعدة إجابات محلية تحتوي بيانات حساسة.
- رقم مراجعة لكل حفظ يمنع تبويبين من الكتابة فوق بعضهما دون تنبيه. عند التعارض يعيد الطالب تحميل آخر حفظ؛ لا تُدمج تعديلات متعارضة بصمت.
- بعد الموعد يُرفض إدخال إجابات جديدة وتُعتمد آخر إجابات وصلت قبل الموعد. المهمة المجدولة تعالج المنتهية حتى مع إغلاق الصفحة، كما يتحقق الخادم عند الطلب التالي. إغلاق المهمة المجدولة قد يؤخر ظهور النتيجة، لكنه لا يمدد الوقت.
- التسليم متكرر الطلبات آمن؛ لا يكرر احتساب النتيجة. المقال غير المجاب عنه درجته صفر، والمقالي المجاب ينتظر المشرف.
- لوحة الشرف تعرض أول 100 طالب، أفضل محاولة نهائية، ثم الأقل زمنًا ثم الأسبق تسليمًا. لا تعرض الهاتف أو المدرسة أو UID. قائمة محاولات الطالب تعرض أحدث 50 محاولة؛ الحد العادي 3، ويؤثر ذلك فقط في تاريخ حسابات الاستثناء الطويل.
- تصحيح المقالي يُعتمد مرة واحدة لمنع التعديل المتزامن. تعديل درجة معتمدة لاحقًا وإعادة بناء الترتيب يحتاج مسار مراجعة إضافيًا، ولا يُجرى بتعديل المستندات يدويًا.

## إشعارات تيليجرام الاختيارية

أحداث التسجيل والدخول والنتيجة تحفظ في `notificationQueue` خادميًا. لا توجد أي إرسال فعلي حتى إعداد البوت ونشر الوظيفة الاختيارية:

```bash
npx firebase functions:secrets:set TELEGRAM_BOT_TOKEN --project abakara-baccalaureate-b0758
npx firebase functions:secrets:set TELEGRAM_CHAT_ID --project abakara-baccalaureate-b0758
npx firebase deploy --project abakara-baccalaureate-b0758 --only functions:sendNotifications
```

الدخول يُسجل بحد مرة للدقيقة لكل حساب. الإرسال كل 5 دقائق، بحد 5 محاولات، وقد يتكرر إشعار إذا توقف التنفيذ بعد التسليم وقبل تسجيل النجاح. لا يؤثر تعطل تيليجرام في حفظ الامتحان. تحقق من هوية المحادثة المستلمة قبل تفعيل الإشعارات التي تحتوي بيانات الطلاب.

## الملفات والخصوصية

`functions/domain.js` للتحقق والحسابات، `service.js` للمعاملات وبيانات الامتحان، `index.js` لنقاط الوصول والمجدولات. `js/app.js` واجهة الطالب، و`js/admin.js` للمشرف. قواعد Firestore تمنع وصول المتصفح المباشر إلى مفاتيح التصحيح أو السجلات الخاصة؛ حتى لوحة الشرف تستعمل دالة تعيد الاسم والدرجة والزمن فقط.

الجلسة تستمر في التبويب الحالي (session persistence). لا تُحفظ كلمة المرور في Firestore أو localStorage. يمكن إضافة App Check وحدود تشغيل أشد بعد تجهيز إعداداته؛ ليس مفعلًا افتراضيًا دون إعداد. المصادقة وقواعد البيانات لا تُغنيان عن مراقبة الاستهلاك ومراجعة النشر.
