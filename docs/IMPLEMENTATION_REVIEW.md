# مراجعة التنفيذ قبل الدمج والنشر

## ما تم تنفيذه
- حساب دائم باسم مستخدم وكلمة مرور، اسم فريد بلا حساسية لحالة الأحرف، والتحقق الخادمي من بيانات الطالب.
- محرك امتحان من 20 سؤالًا/20 درجة، 30 دقيقة من وقت الخادم، 3 محاولات بمعاملات Firestore، وصلاحية منفصلة لاستثناء الحسابين المحددين.
- حفظ تلقائي ويدوي، استئناف بعد تحديث الصفحة، كشف تعارض التبويبات، تسليم مرة واحدة، وانتهاء الوقت حتى عند إغلاق الصفحة.
- تصحيح الاختيارات خادميًا، مراجعة المقالي للمشرف، نتيجة معلقة ثم نهائية، وأفضل محاولة في لوحة الشرف.
- لوحة إدارة ببيانات الطلاب وآخر دخول وأفضل درجة ومراجعة المقالي. وظائف إدارة محمية بـ custom claims.
- طابور إشعارات تيليجرام اختياري لا يعطل الامتحان، وأدوات إعداد ونشر مقيّدة بالمشروع الصحيح.

## الاختبارات
- 16 اختبار وحدة وخدمة: التحقق، التزامن، منع المحاولة الرابعة، الاستثناء، التسليم المتكرر، الحفظ القديم، تجاهل الإجابات المتأخرة، تعليق المقالي ثم نشر الدرجة.
- اختبار تكامل مع محاكي Auth وFirestore: بروتوكول callable الحقيقي والتحقق من التوكن، رفض غير المسجل وغير المشرف، منع قراءة بيانات طالب آخر، منع القراءة/الكتابة المباشرة بقواعد Firestore، وحفظ النتيجة والترتيب.
- 4 اختبارات متصفح على الهاتف والكمبيوتر: حالة الإعداد غير المكتمل، ودورة التسجيل/البيانات/الحل/الحفظ/إعادة التحميل/الاستئناف/التسليم/تصحيح المقالي/النتيجة.
- فحص syntax وJSON وروابط أصول البناء ومعرفات HTML، والبناء القابل للتكرار بواسطة ملفات القفل.
- اختبار التكامل هنا شغّل **نفس HTTP handlers المصدرة للإنتاج** عبر مضيف TCP محلي، لأن بيئة الاختبار لا تسمح بمقابس Unix التي يستخدمها محاكي Functions. محاكيا Auth وFirestore حقيقيان؛ لم يتم استدعاء مشروع الإنتاج. استخدم `npm run test:emulator:all:tcp` لإعادة هذا الاختبار.
- المهمة المجدولة وطلب تيليجرام لم يختبرا في الإنتاج؛ منطق إنهاء المحاولة اختبر مباشرة وعبر callable، وإرسال تيليجرام يبقى خطوة تفعيل واختبار منفصلة بعد اعتماد المحادثة المستقبلة.

## متطلبات التشغيل المتبقية
1. إعداد تطبيق Firebase العام الكامل، خصوصًا apiKey، في `js/config.js` ثم إعادة البناء.
2. عشرون سؤالًا معتمدًا وتوزيع درجاتها، وتحديد نصوص المنهج واسم القصة ومراجعة محتواها. لا أسئلة حقيقية مستخرجة أو مخترعة ضمن هذا التغيير.
3. UID المشرف وUID الحسابين المستثنيين. لا صلاحيات تلقائية ولا كلمات مرور افتراضية.
4. مراجعة إعدادات Firebase الحالية والموافقة على نشر الوظائف والفهارس وأي تغيير للقواعد. لم تنفّذ هذه التغييرات في الإنتاج.
5. لتفعيل تيليجرام لاحقًا: إعداد السرّين والتحقق من المحادثة المستقبلة ثم نشر الوظيفة الاختيارية.

## حدود واضحة
- الحسابات التجريبية القديمة لا تهاجر تلقائيًا. حسابات البريد الداخلي الجديدة تدعم استعادة كلمة المرور من المشرف بعد التحقق من الهوية؛ لا بريد استرجاع وهمي.
- حد المحاولات لكل حساب، ولا يمنع شخصًا من إنشاء حسابات أخرى؛ الهاتف لا يخضع للتحقق برسالة SMS.
- الإجابات غير المتصلة لا تحفظ خارج الصفحة؛ لا تدّعي الواجهة نجاح حفظ لم يؤكده الخادم.
- تصحيح المقالي النهائي يعتمد مرة واحدة. مراجعة درجة معتمدة تحتاج مسارًا منفصلًا لإعادة حساب أفضل محاولة.
- لا نشر مباشر للواجهة ولا دمج تلقائي في main ضمن هذا التنفيذ.
